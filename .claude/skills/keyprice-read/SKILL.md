# keyprice-read — 關鍵價截圖判讀

## 這是什麼(先讀這段)

這不是一支腳本,是**判讀員的判斷行為**。你(Claude)用**視覺**讀朋友的 TradingView
截圖,依規格產出關鍵價判讀。程式只負責一件事:跟 watchlist.json / kline.db 做**確定性
交叉驗證**(helper `scripts/keyprice_verify.py`)。

**最高原則:不確定就標記,不要猜。** 判讀結果要讓使用者能用「同樣的複核方式」檢查——
每個可疑點都要標出來、附依據,而不是給一個看起來乾淨其實猜的答案。

**流程**:截圖放 `keyprice_inbox/` → 跑本 skill → 產出 `判讀結果` + `需複核清單`
→ 使用者複核 → 使用者**手動**上架。**本 skill 絕不上架、絕不動線上。**

---

## 執行步驟

### Step 0 — ★每次都重新載入規格(不靠記憶)

依序完整讀入,任何一份缺失就**停下並回報**,不要憑記憶硬判:

1. `docs/keyprice/關鍵價判讀_Project資訊包.md`
   —— 輸出格式(§1)、欄位規則、判讀鐵律、忽略清單、三個陷阱、分類關鍵字表、排除清單。
2. `docs/keyprice/標準輸出範例.md`
   —— 9/15 那批實際判讀,**示範五種判斷行為**(見下),是行為範本不只是格式範本。
3. **watchlist 真值 = `config/watchlist.json`**(★不是 md 快照)。
   先跑一次重生人看的快照,確保不過期:
   ```
   python3 .claude/skills/keyprice-read/scripts/keyprice_verify.py gen-md
   ```

讀完後,用**資訊包的規格**判讀,以下步驟是流程骨架,細則一律以資訊包為準。

### Step 1 — 列出待判讀截圖

掃 `keyprice_inbox/`(不含 `output/`)所有 `*.png / *.jpg / *.jpeg`,依檔名排序。
逐張用 Read 工具讀入(視覺)。**檔名是 LINE 相簿流水號、不含股票資訊 → 代號只能從圖上讀。**

### Step 2 — ★代號辨識:三重驗證(最不能錯的一步)

之前踩過:微星 2377 被誤認成 2399(映泰),抓了 211 根別家 K 線。所以**三關全過才採用**:

1. **讀圖**:從 TradingView **左上角**讀「代號 + 名稱 + 右軸現價」。
2. **查表**:把代號丟 helper 驗證(可一次多碼):
   ```
   python3 .claude/skills/keyprice-read/scripts/keyprice_verify.py verify 2377 6669 ...
   ```
   - `in_watchlist=false` → **標「需人工確認」,不要自己挑一個相近代號**。
   - `watchlist_name` 與圖上名稱**不符** → 標「需人工確認」(可能讀錯代號)。
   - `ambiguous`(同碼多市場)→ 標「需人工確認」。
3. **現價-價格把關(★主要:近一年區間;次要:10% 僅供參考)**:
   - **主要判定**:圖上右軸現價**是否落在** helper 回的 `[low_1y, high_1y]` 區間內。
     區間內 → 過;**區間外(尤其 >2x)→ 疑讀錯代號/讀錯股,標「需人工確認」**。
   - **次要註記(僅供參考,不作判定)**:現價 vs `kline_latest_close` 差 >10% 時,在備註記一行,
     但**不因此判失敗**。
   > ★為什麼主要用「近一年區間」而不是「10% vs 最近收盤」(2026-09-20 dry-run 後定,勿改回去):
   > 「近一年區間」不受截圖新舊影響 —— 舊截圖(如 2026-07-19 那批)的現價本來就跟今天收盤差幾個月
   > 價差(富世達 7→9 月漲 41%),但只要現價落在近一年區間內、就不是讀錯代號。
   > 「10% vs 最近收盤」綁死「截圖必須是最近的」這個假設,對舊截圖會整批誤報,故降為次要。
   > 真正抓「讀錯代號」的鐵證是:現價**遠離**近一年區間(價位交叉驗證 >2x 同理)。

**★備註必須帶辨識依據**,讓使用者一眼看出驗證過,例如:
> 代號 2377 讀自圖左上,名稱「微星」與 watchlist 一致,現價 141.5 落在近一年 85~173.5 區間內
> (與 kline 最近收盤 155 差 8.7%,僅供參考)

三關任一不過 → 該檔照樣輸出判讀,但**開頭標明「⚠️ 需人工確認代號」**並寫清楚哪關不過。

### Step 3 — 判讀線與區域(依資訊包 §1 + 五種判斷行為)

嚴格照資訊包的欄位規則與鐵律。輸出格式(§1):
```
[市場:代號 名稱]  # 現價: XXX(右軸)
線(實線): 價格 | 顏色 | 文字 | 形容詞
區域: 下緣 | 上緣 | 文字 | 形容詞
備註: (複核點 + 辨識依據 + 忽略了什麼)
```

**★五種判斷行為(比格式正確更重要,務必比照範例做到):**

1. **遇矛盾不自己選,兩個都記 + 標需複核。**
   例:文字寫「小內撐 344」但目測約 386 → **照文字記 344**,備註「文字 344 vs 目測 ~386,不一致需複核」。
   例:「內撐 26」目測 24.2 → 同樣照文字記、備註不一致。
2. **主動提出「這可能該是另一種東西」。**
   例:兩條線 92.0 與 89.8 很近、看不出色塊 → 暫記兩條線,備註「若其實是區域,改成 89.8–92.0」。
3. **說明「為什麼這個不排除」。**
   例:「起漲買盤訂單塊」→ 備註「含『訂單塊』故歸訂單塊;排除清單只有『起漲K』不含它」。
4. **記錄忽略了什麼**(讓使用者知道你有看到、只是照規則不記)。
   例:「XXX、XXX 為 SMA(均線),已忽略」「1 個橘圈已忽略」「起漲K 方框依規則忽略」。
5. **規則本身模糊就反問。**
   例:「小內撐 344」→ 備註「需複核:『小』要不要拆到形容詞欄?」

**★★★ 排除清單 vs 忽略清單 —— 兩者處理完全不同,別搞混(2026-09-20 修正)★★★**

判讀員的職責 = **忠實記錄圖上所有線/區塊**。排除是**下游 convert 的事**,不是判讀階段就丟。

- **忽略清單**(方框指 K 棒、均線 SMA/MA、量能色塊、箭頭、圈記):
  這些**本來就不是水平線/區塊** → **不記成線/區域**,只在備註提一句(如「起漲K 方框依規則忽略」)。
- **排除清單**(文字型:`大戶空單成本價`、`多頭起漲點`、`起漲K`(當它是**水平線**而非方框時)、
  `重要起始K棒`、`谷貼`…):
  這些是圖上**真的畫了一條線/一個區塊** → **★judgment 階段一定要照記**(含價格、顏色、原始文字),
  **只在備註註明**「此詞在下游排除清單內,convert 會丟棄」。
  **★絕不在判讀階段就不記** —— 那會讓使用者複核時看不到圖上有這條線,等於幫下游做了不該判讀員做的決定。
  例:祥碩紅線「大戶空單成本價 1740」→ 照記成線(價格 1740、顏色 紅、文字「大戶空單成本價 1740」),
  備註寫「『大戶空單成本價』在下游排除清單,convert 會丟棄,但判讀照實記」。

  分辨關鍵:**它在圖上是「一條水平線/一個色塊」還是「指向某根 K 棒的方框/圈」?**
  是線/塊 → 記(即使文字在排除清單);是方框/圈/均線 → 不記(忽略清單)。

### Step 4 — 價位交叉驗證(用 helper,只標不改)

判讀出的**每個價位**,對照 helper 回的該股 `low_1y ~ high_1y`:
- 價位落在近一年區間外 **>2x**(小數點位移、看錯行的特徵)→ **列入需複核**。
- ★**只標記,絕不自動修正**。註:若該股剛除權,整段可能偏移 → 也只標「請確認」,無害。

### Step 5 — 產出兩份檔到 `keyprice_inbox/output/`

用今天日期(跑 `date +%F` 取):
- `判讀結果_<日期>.md`:所有檔,完全照資訊包 §1 格式。
- `需複核清單_<日期>.md`:單獨列——
  - **清單外新詞彙**(文字/形容詞不在資訊包分類關鍵字表/排除清單 → 上架會被靜默跳過,**必須問朋友**)
  - 被遮擋/被裁的價位
  - 邊界目測的(標 `~`)
  - 顏色不確定的
  - 無文字的框(確認真無名 or 沒讀到)
  - 代號三重驗證未全過的
  - 價位交叉驗證命中的(>2x)

### Step 6 — 收尾

在對話摘要:判讀幾檔、需複核幾項、輸出檔路徑。**停在這裡,不上架、不 commit、不動線上。**

## ★絕對不要做(違反即失敗)

- **不正規化、不合併、不改字** —— 忠實記錄原文(錯字、簡稱都照抄)。
- **不自己決定新詞歸哪類** —— 標出來問使用者。
- **不把這些記成線或區塊**:圈記 K 棒的方框、均線(SMA/MA)、量能色塊、箭頭。
- **文字沒有寫「(無)」**,絕對不要留純空格 / 空字串。
- **不猜代號**:三重驗證不過就標「需人工確認」,不要挑相近的。
- **不上架、不改 config/、不動 docs/data/、不 commit**。

## 新詞判定(給 Step 5 用)

「清單」= 資訊包裡的**分類關鍵字表 + 排除清單**。判讀出的每個「文字/形容詞」原文,
若在清單內 → 正常;若**不在** → 是新詞 → 進需複核清單(不要自己歸類、不要改成相近的既有詞)。

## helper 速查
- `keyprice_verify.py verify CODE...` → 每碼回 {in_watchlist, watchlist_name, kline_latest_close, high_1y, low_1y}(真值 = config/watchlist.json + kline.db)。
- `keyprice_verify.py gen-md` → 從 watchlist.json 重生 `docs/keyprice/watchlist_名單.md`(人看用,勿手改)。
