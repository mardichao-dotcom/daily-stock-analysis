# 關鍵價截圖判讀 — Project 資訊包

> 用途:給「截圖判讀關鍵價」這個新 project 的完整規格。
> 目標:朋友貼一張看盤截圖(手繪關鍵價) → 判讀成標準格式 → 交付上架到台股儀表板系統。
> 匯出:2026-09-15 ｜ 來源:台股儀表板 `tools/convert_key_prices.py` + `config/`

---

## 0. 這個 Project 在做什麼

1. **輸入**:朋友在 TradingView 手繪的關鍵價**截圖**(水平線 + 色塊區域 + 文字標註)。
2. **判讀**:把截圖忠實轉成下方「判讀輸出格式」的純文字。
3. **交付**:輸出檔交給台股儀表板上架(上架端會跑 `convert_key_prices.py` → key_prices.json → 計分/畫圖)。

**判讀員的天職 = 忠實記錄,不評估、不正規化、不合併、不改字。** 看到什麼寫什麼。
分類、計分、配色都是**下游系統**的事,判讀階段只負責「把圖上的東西精確變成文字」。

---

## 1. 判讀輸出格式(★ 這就是要交付的格式)

每檔一個區塊,結構如下:

```
[市場:代號 名稱]  # 現價: XXX(右軸)

線(實線):
價格: XXX | 顏色: X | 文字: X | 形容詞: X
價格: XXX | 顏色: X | 文字: X | 形容詞: X

區域:
區域下緣: XXX | 區域上緣: XXX | 文字: X | 形容詞: X

備註: (自由文字,記錄複核點/目測/被遮擋等)
```

### 欄位規則
| 欄位 | 規則 |
|---|---|
| **市場:代號** | 交易所前綴 + 代號,例 `TWSE:2330`、`TPEX:6223`、`NASDAQ:NVDA`、`TSE:6594`、`OMXCOP:MAERSK_B`(見 §6 前綴表) |
| **名稱** | 公司中文名;國際股未收到中文名單時用英文代號,標「★名稱待對照」 |
| **現價** | 一律以**右軸**為準(截圖右側價格軸),寫在標頭 `# 現價:` |
| **價格 / 區域下緣 / 區域上緣** | 數字。可含千分位逗號(2,025)、目測用 `~`(~1,150)。**原樣保留,別四捨五入** |
| **顏色** | 只有三種:`紅` / `黑` / `灰`。不確定寫 `灰?(不確定)` 並在備註說明 |
| **文字** | 圖上該線/區塊旁的**原始文字**,一字不改。沒有就寫 `(無)` |
| **形容詞** | 只有五種:`(無)` / `重要` / `小` / `短線` / `預估`。單獨出現的「重要」放這欄、文字欄寫 `(無)` |

### 判讀鐵律(從歷次上架累積)
- **規則 1b — 線與區域邊界重疊,只記區域**:若一條線正好是某區塊的上緣或下緣,不重複記那條線,只記區域。
- **★ 需複核標記**:判讀不確定處(顏色淡、位置目測、文字被遮/被裁)在該檔 `備註:` 說明,交付前請朋友複核。
- **`~` 波浪號 = 目測邊界**:無右軸精確數字、憑目視估的,價格前加 `~`,原樣保留(上架端會去掉波浪號取數字,但保留標記讓人知道是估的)。
- **`★註記`**:形容詞欄後可加 `★邊界不確定` 之類,上架端會拆成 annotations 保留。
- **文字被裁/被遮**:忠實記已見部分 + 標 `?`,例 `賣盤訂單塊(? 右緣被裁,僅見「賣盤訂」)`。

### 忽略清單(圖上有、但**不要**記成線/區塊)
- **圈記 K 棒的方框註記**(橘圈、方框指某根 K 棒):如「起漲K」「多頭起漲點」「重要起始K棒」「多頭最後防線(方框指均線交會K棒)」——這些是「指向某根 K 棒」而非水平線/區塊,忽略,只在備註提一下。
- **均線(MA Ribbon)**:飄動的均線不是關鍵價。
- **成交量區的色塊**(圖表底部量能區):不是價格關鍵價。
- **手繪箭頭 / 走勢預測**:忽略。

## 2. 下游怎麼分類(判讀員不需分類,但了解有助於判讀精確)

上架端 `convert_key_prices.py` 用「**文字含某關鍵字就歸某類**」自動分類。判讀員**不用**填類別,但知道規則可避免踩雷。

### 區域(area)類別 — 依此順序比對,**先命中者贏**
| 順序 | 類別 | 觸發關鍵字 |
|---|---|---|
| 1 | order_block(訂單塊) | `訂單塊`(含前綴:買盤/賣盤/底部/短線…都算) |
| 2 | poc | `POC`、`籌碼集中區` |
| 3 | fvg | `FVG` |
| 4 | gap(跳空) | `跳空缺口`、`跳空區口` |
| 5 | break_block(破壞塊) | `破壞塊`(**只此三字**) |
| 6 | unclassified(中性) | `賣壓`、`重要撐轉`、`短線買盤`、`多頭最後防線` |

### 線(line)類別
| 類別 | 觸發關鍵字 |
|---|---|
| support_transfer | 撐轉、前高、壓力位、賣壓、價格轉換、中繼、支撐、阻力、歷史高點、撐轉位、深底、短線買盤底部 |
| inner_support | 內撐、內部撐轉 |
| whale_cost | 大戶成本、多單大戶成本、預估大戶成本 |
| key_price(預設) | 以上都不含 → key_price(純數字文字也是) |

### 排除清單(文字含這些 → 整個丟棄不計分)
`大戶空單成本價`、`多頭起漲點`、`起漲K`、`起漲 K`、`重要起始K棒`、`重要起始 K 棒`、`谷貼`

## 3. ★ 判讀時必須避開的三個陷阱(直接影響上架正確性)

1. **空文字 vs 空格**:框沒文字要寫 `(無)`(→ 歸 unclassified、會計分)。**絕對不要留純空格**——純空格會被判成「無對映 → 靜默跳過、不計分」。要嘛寫 `(無)`,要嘛寫真實文字。

2. **有文字但用了清單外的新詞 → 會被靜默跳過(區塊消失)**:區域文字若不含上表任何關鍵字(例如自創「支撐帶」「主力成本區」),**不會**變 unclassified,而是**整個區塊被丟棄、只在 log 記一行**。所以判讀出現**新詞彙時,交付前一定要標出來問朋友**要歸哪類,別讓它靜默消失。(unclassified 只收「空文字」和上表那四個特定詞。)

3. **「訂單塊」是最強吸磁**:任何含「訂單塊」三字的詞一律歸 order_block(權重 2),不管前面寫買/賣/短線。若朋友寫「賣壓訂單塊」想表達壓力,系統仍當一般訂單塊算 2 分——方向性會被抹平。判讀忠實記原文即可,但這點值得跟朋友確認用詞。

## 4. 下游計分邏輯(判讀員參考,理解「為什麼要精確」)

- **顏色乘數(只作用於「線」)**:紅 ×1.5、黑 ×1.0、灰 ×0.7。所以線的顏色判讀錯,分數差很多。**區域不套顏色。**
- **形容詞**:重要 = +1(最後加)、小 = ×0.7、短線 = ×1.0(無作用)、預估 = ×0.9。
- **區域基礎分**:order_block=2,其餘(poc/fvg/gap/break_block/unclassified)=1。
- **線基礎分**:key_price/support_transfer/inner_support/whale_cost 都=1。
- **觸發**:區塊 = 當天 K 棒(含影線)碰到區間即 +N;線 = 要「站上並站穩」(碰到+隔天開收都在線上)才計分。
- **系統目前不看距離、不分區塊在現價上方或下方**(買盤支撐塊 vs 賣盤壓力塊給同分)——這是已知待改進點,判讀階段照實記即可。

---

## 5. 顏色 / 形容詞 對映(上架端會做的轉換,判讀用中文即可)

- 顏色:`紅`→red、`黑`→black、`灰`→gray(判讀寫中文)
- 形容詞:`(無)`→null、`重要`→important、`小`→small、`短線`→short_term、`預估`→estimated
- 價格:去千分位逗號、去 `~` 後存字串(不轉 float,因為是資料庫主鍵識別碼,要 string-stable)

## 8. 上架端格式(交付後,系統會把判讀轉成這個)

判讀輸出交付後,上架端轉成 `key_prices_clean_v3.md`,每檔:
```
## 板塊名(由 watchlist 反查,判讀員不用填)
### [TWSE:2330 台積電]
線(實線):
- 價格: 2025 | 顏色: 紅 | 文字: 2025 | 形容詞: (無)
區域:
- 區域下緣: 2130 | 區域上緣: 2180 | 文字: 買盤訂單塊 | 形容詞: (無)
```
再跑 `convert_key_prices.py` → `config/key_prices.json`(140 檔權威真值)→ 計分 + 畫圖。

**判讀員不用管板塊(##)** —— 板塊由 watchlist 的 sector 自動反查填入。判讀只交「### 這一塊以下」。

## 9. 交付前 checklist(判讀員自檢)

- [ ] 每檔標頭 `[市場:代號 名稱] # 現價:` 齊全,代號對照過 watchlist 名單
- [ ] 顏色只用 紅/黑/灰;不確定的標 `?` + 備註
- [ ] 文字忠實照抄;沒有寫 `(無)`,**不要留空格**
- [ ] 形容詞只用 (無)/重要/小/短線/預估
- [ ] 線與區域邊界重疊 → 只記區域(規則 1b)
- [ ] 目測邊界標 `~`;被遮/被裁標 `?` + 備註
- [ ] 圈記 K 棒 / 均線 / 量能色塊 / 箭頭 → 不記(備註提一下)
- [ ] ★ **出現清單外新詞彙 → 標出來,交付時列一份「新詞清單」問朋友歸類**(否則會被靜默跳過)
- [ ] 需複核處都寫進該檔 `備註:`
